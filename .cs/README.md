Native cross-session messaging adopted, Windows dropped (2026-08-08). Claude Code 2.1.224 shipped session-to-session messaging over a per-session AF_UNIX socket, so the question was what cs should hand over to it. A Fable audit of the installed bundle established the mechanics — kernel-verified peer pid but a forgeable claimed name, an own-child check that walks live `ps` ancestry and so cannot verify a poster that has exited, `peerProtocol: 1` already growing `bridge:`/`did:` schemes — and concluded delivery would be held rather than delivered, because the bundle default for the mode-attestation gate is false. A single live message to a peer session disproved it: the reply came back with `from-mode="bypass"` in the envelope, the gate resolves ON for this account, and bypass-to-bypass auto-accepts. Fable's own post-mortem named the error precisely: it verified a client-side default and then inferred a server-resolved runtime value from it. The decision stood regardless — cs keeps the maildir, which is the half native has no answer for (durability, threads, the sender's own copy, `--kind task` feeding the queue), and gives up nothing, since live delivery already happens in-process via SendMessage.

What cs did adopt is the discovery half: `~/.claude/sessions/<pid>.json` carries name, cwd, tmux target, socket path and live agent state. `cs -live` and the TUI's state row now show `busy`/`waiting`/`idle`, cross-checked against a live pid whose recorded process start still matches so a recycled pid cannot keep a dead session looking busy. The first implementation passed its test and returned nothing on real data — Claude Code records that start time in UTC while `ps -o lstart=` prints the caller's zone and pads the field — and the test could not have caught it, because the fixture generated the expected value with the same `ps` call the code compared against. The Rust side was restructured so it can fail: a pure parser tested against a verbatim on-disk record. A follow-up pass made the whole set read in one jq/ps/awk instead of two forks per session, measured at 1 jq + 1 ps over eight live sessions, down from sixteen.

Multi-provider rewriter (2026-08-13, merged at `c72e20a`, deployed): `ctrl+g` now rewrites through OpenAI or Gemini as well as Claude. `CS_REWRITE_PROVIDER=openai|gemini` routes to a new `prompt-rewriter-vendor.sh`, which prefers that vendor's CLI when its binary is on PATH — `codex` and `agy`, on Alex's subscriptions — and falls back to the vendor's API otherwise. Three failure modes the "non-zero to decline" contract does not anticipate drove the design, all found empirically rather than reasoned about. `agy` prints `CLI error: …` on stdout and exits 0, so that string would have become the user's next message.
