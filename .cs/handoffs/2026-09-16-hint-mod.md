## 2. Settled and rejected

**Design, agreed with Alex this conversation (his picks: facts 1-4 yes,
tips yes as fallback):**

- Mod `mods/cs-hint/` beside `cs-rotate`: `.claude-plugin/plugin.json`,
  `hooks/hooks.json`, `hooks/register.tsx`, `test/register.test.ts`.
- Hooks `ui.render { component: 'PromptHint' }`. Props (read in source,
  `claude-code.d.ts` RenderPropsOf.PromptHint): `isDraft`, `isWorking`
  (read-only), `hint: string` (one string; a rewrite replaces the line via
  `next({...e, props: {...e.props, hint}})`, or the hook draws its own tree).
  No hotkeys on this site (band only). One dim line; keep it short, it
  truncates.
- **Priority** for the line: unread mail > armed handoff > queue/gate >
  resumed handoff's next step > tip > engine hint. At most two facts joined
  by ` · `.
- **isDraft true → return the engine's hint untouched** (shortcuts matter
  while typing). Alex accepted this.
- **Lead conversation only**: same check as cs-rotate `ownsRotation`
  (`.cs/local` exists, no `.cs/local/disabled`, `claude_session_id` in
  `.cs/local/state` equals `$.session.id()`). Outside a cs session: silent.
- **Refresh**: re-read facts on `turn.complete` and a `$.clock.every(5000)`
  → `$.ui.invalidate('ui.render')` (cap is 10/s; measured rule in the type
  file). Tips change on `turn.complete` only, never on the timer (no
  movement while reading).
- **Tips**: fixed list in the mod (~25), never generated. Context-aware
  pick: worktree session (`cs_mode`/`task_branch` in `.cs/local/state`) →
  `/finish`; plain session → `/feature <name>`; Fable session (model id from
  `$.session` or the `fable` statusline segment) → caps consent tip. Others
  rotate by turn count. Candidates Alex saw: `/rotate hands a heavy
  conversation to a fresh one`, `cs -msg <session> "…" mails another
  session`, `/feature <name> spawns a worktree session from a brief`,
  `cs -live shows who is idle, busy or in a shell`, `/finish <name> lands a
  feature branch`, `cs -secrets set reads the value from stdin, never argv`,
  `press 1 on the band to rotate`, `cs -doctor names every hook that
  injects context`.
- **Off switch**: `CS_NO_HINTS=1` in env (read via `$.env.get`, literal
  name — `claude plugin validate` lists what a module reads) OR a
  `hints: off` line in `.cs/local/state`. Off → engine hint untouched.
  Reason: a user-visible surface needs revocable consent
  (`feedback_visible_surfaces_need_consent`).
- **Rejected**: ctx % or limits on this line (status line owns them);
  anything needing a press; timer-driven tip rotation; generated tips.

**Fact sources, MEASURED on disk this conversation:**

- Mail: `.cs/local/mail/{cur,new,notified,out,tmp,woke}`. Unread = entries in
  `.cs/local/mail/new/`. Message files are JSON, e.g.
  `{"id":"…","ts":1784400076,"from":"smoke","actor":"…","kind":"result","ref":null,"body":…}`;
  `from` is `""` not null outside a cs session (`project_mail_from_empty_string`).
  Hint shape: `2 messages from <from> · /msg` (or `cs -msg`).

  only when `.cs/handoffs/<name>` frontmatter says `status: unconsumed`
  (copy `isUnconsumed` from cs-rotate exactly; it mirrors
  `hooks/session-start.sh` `_handoff_is_unconsumed`). Below the band
  threshold this is invisible today.
- Queue: `.cs/local/queue/` is a DIRECTORY of task files (lib/55-queue.sh:43
  `mkdir -p "$qdir/queue" "$qdir/queue.tmp"`), `.cs/local/queue.state`
  holds one word (read `idle` today), `.cs/local/queue.declined` marks a
  declined gate (lib/55-queue.sh:95), `queue.done` exists too. Hint: `N queued`
  plus `gate declined`/`gate waiting` when the marker says so — read
  lib/55-queue.sh for the exact gate state before asserting a word.
